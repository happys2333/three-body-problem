# 统一 F 键提问

2026-10-31：按住 F 说话，松开后转写并自动提问。取消预设问题、人物选择和 V 键录音入口；正常语音交流时收起文字框，仅在麦克风或转写不可用时展开替代输入。

## Unity 负责的规则

- 每次按下 F 时，重新查询当前场景中有效、可交谈的人物。只有一个人时由该人物接收；多人时优先选择视野内未被遮挡、与视线夹角最小的人物，夹角接近时取距离较近者。没有可见人物时仍以视线最接近的有效人物接收，不设固定交谈距离。
- 接收者在录音开始前锁定。录音、转写或等待回答时转头、走远、经过剧情阶段切换，都不会把同一句问题改投给别人。
- 新一次 F 提问会中止上一次待处理的提问和声音。暂停、关闭对话、切出应用时取消采集；旧转写结果不能提交到新的一轮。原目标失效时取消，不暗中改选别人。
- 不因烈日、开场问答计数或普通剧情阶段禁止提问。标题、暂停、观察簿、总结、场景加载和调试预览不采集录音。
- 无选项后，宫廷／质询的必要交流结束并播完回答，再继续剧情；原先依赖 F 确认的过渡阶段自动继续。F 始终只用于提问。

## LLM 负责的判断

是否明确向另一位人物提问，由 LLM 结合整句话理解。Unity 和网关不使用姓名关键词或正则表达式决定转交。普通提及、询问他人的情况、引用他人的话，不应自动改换接收者。

Unity 向 `/dialogue` 提供最初接收者 `recipientId`、原始 `utterance`、本角色的独立 `history`，以及在场人物名单 `interlocutors`。名单的 `id` 唯一标识人物实例；`npcId` 指定角色人格，`displayName` 和 `aliases` 帮助模型理解称呼。

正常回答：

```json
{"speech":"角色的回答","gesture":"talk","storyIntent":"continue","targetId":""}
```

LLM 决定转交：

```json
{"speech":"","gesture":"think","storyIntent":"continue","targetId":"在场名单中的人物实例 id"}
```

转交时，网关强制清空原接收者的台词和剧情意图。Unity 再次验证目标仍然有效，用目标角色自己的历史重新请求回答；第二次请求 `allowHandoff=false`，不允许循环转交。原接收者不显示回答、不发声、不把这次问答写入自己的记忆。最终只有目标人物记住并回答这句话。

主要人物使用独立角色提示词。居民、朝歌卫兵和中世纪守卫共用 `bystander.txt`，各个实例的对话历史仍然隔离。项目现有主角包含姬昌／周文王、纣王、教皇、学者和达芬奇；姬发不是姬昌的别名，也没有被凭空加入当前场景。

## 接入与验证边界

本机语音识别仍由 Unity 录音、本机 ASR 转写。网关默认离线剧情回退；只有启动网关在线模式并提供服务端模型凭据后，才会运行 LLM 的语义转交。离线模式保留最初接收者，不假装理解点名意图。

网关测试使用模拟上游验证协议、静默转交、在场名单限制和单次转交；这不证明真实 LLM 对自然语言指向的准确率。Unity 测试覆盖视线选择、距离与遮挡、对象锁定和旧结果拒绝。真实麦克风权限、现场噪声和真实模型的语义效果需要单独实测；源码变更也不会自动更新已有独立 `.app`。本轮已更新独立包，具体结果与限制见 [2026-10-31 验收](Dialogue/2026-10-31/README.md)。
