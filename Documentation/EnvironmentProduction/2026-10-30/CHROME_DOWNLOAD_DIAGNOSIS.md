# Chrome 下载排查与继续导出

排查日期：2026-10-30 至 2026-10-31。对象为用户已登录 Chrome 中的腾讯混元 3D，继续取得本批剩余模型，不重新生成、不消耗额度。

## 已核实的事实

- 起初实际为 6 件已下载、1 件曾出现 `ERR_BLOCKED_BY_CLIENT`、另外 13 件尚未逐一导出。不能把未下载全部写成已被 Chrome 拦截。
- 本轮从正常模型菜单导出 FBX，已多次取得完整文件。Chrome 下载托盘显示完成，原档和 Unity 工程副本通过哈希核对。
- 混元网站信息中“连接是安全的”，“自动下载项”已开启。这是检查时已有的设置，本轮没有修改，见[网站权限截图](DownloadProof/ChromePermissions.jpg)。
- AdBlock 已安装并有本页访问权限，但检查时本页拦截数为 0。仅凭扩展已安装，不能断言它导致此前的错误。
- 青铜火盆、锻铁火盆先后在 Chrome 原生下载面板明确显示“请检查互联网连接状况”，点击“继续下载”后均恢复传输并完成。这两次属于传输中断，并非安全拦截。见[青铜火盆中断](DownloadProof/ChromeNetworkFailure.jpg)、[锻铁火盆中断](DownloadProof/FinalNetworkInterruption.jpg)及[最终完成记录](DownloadProof/CompletedDownloads.jpg)。
- 自动化的 `waitForEvent('download')` 曾等待超时，后续检查仍取得了完整文件，Chrome 也显示完成。短时间等待超时不等于 Chrome 安全拦截，也不能单独证明完成通知丢失。
- 下载操作之后曾出现 `Page.getFrameTree` / `Runtime.evaluate` 控制超时。重新取得同一个标签页的控制句柄后，页面读取立即恢复。本轮没有重新登录或更换浏览器。
- 模型页连续使用时显示约 2.7 GB 内存占用。最后一件导出期间，Chrome 任务管理器的一个采样显示 2.5 GB、CPU 16.9、网络 0，见[任务状态截图](DownloadProof/ChromeTaskState.jpg)。这些瞬时观察不能单独证明下载问题由内存或 CPU 导致。

## 本次采用的恢复方式

1. 每次先核对模型列表位置、PBR 第一候选、实际模型预览与面数。
2. 使用平台可见的“下载 → FBX”控件，不把下载网址当网页打开，不通过脚本请求签名导出 URL。
3. 控制读取超时后，重新绑定同一个已登录标签页；持续等待仍无文件、也无下载条目时，可正常刷新已保存的资产列表，重新打开同一模型后再导出。本轮使用过此方法，没有重新生成模型。不要仅因一次短超时就重建浏览器或反复提交导出。
4. 检查 Chrome 原生下载面板。若明确显示网络中断，使用该条目的“继续下载”；不要把“网络中断”写成“安全拦截”。安全警告则保留给用户处理。
5. 以 Chrome 完成记录和完整的本地 `.fbx` 为完成信号。归档前检查二进制 FBX 文件头、稳定大小与 SHA-256，核对原档和工程副本。
6. 若出现明确的危险文件、证书或不安全下载警告，应保留提示让用户判断；本轮未通过此类警告放行文件，也未关闭安全浏览或扩展。

FBX 目前可正常取得，所以 GLB 仅作为排查方向提出；没有把未完成的 GLB 测试写成通过，也没有用其他格式替代本批 FBX 原档。

## 结论与限制

本轮确认了网络中断，也观察到导出期间的控制读取超时和完成等待超时。部分模型在等待数分钟后仍正常完成，因此旧流程不能仅凭超时就认定下载被拦截。当前将导出请求、控制超时、Chrome 下载记录和最终文件分开记录，逐件正常导出并校验落盘文件。

重新绑定同一标签页在部分情况下恢复了读取；在另一些情况下仍需等待。它是操作恢复手段，不足以证明唯一根因是控制连接，或证明导出服务、网络、扩展中哪一项有故障。

本轮另外观察到一份较早导出的火盆延迟到达。它与已归档火盆的顶点、索引及 UV 数组指纹完全相同，未计入市集货担，保留在下载目录并从素材库隔离。

当前结果：补齐剩余十四件，全批二十件 PBR FBX 已归档，源文件及工程副本的哈希、独立几何指纹和四张内嵌 PNG 均通过检查。Unity 资源刷新完成，检查时控制台没有错误或警告。新增十四件尚未完成预制体与美术加工，技术检查通过的预制体仍只有原来的六件，最终美术验收仍为零。见[全批源文件检查](source-file-audit.json)和[交付清单](delivery.json)。

此前那一次 `ERR_BLOCKED_BY_CLIENT` 没有在本轮重新复现，不能据此宣布已经找到唯一根因，或声称 Chrome 本身、AdBlock、旧链接一定有问题。若其他网站继续出现，应保留具体提示与发生网址，区分安全警告、自动下载权限、扩展阻止和自动化通知丢失。

Chromium 将 `ERR_BLOCKED_BY_CLIENT` 定义为客户端阻止请求；它不同于文件检测到病毒或管理员策略阻止。[Chromium 错误定义](https://chromium.googlesource.com/chromium/src/+/9d77295e/net/base/net_error_list.h)

Chrome 的批量下载权限可按网站管理，官方路径为“设置 → 隐私和安全 → 网站设置 → 更多权限 → 自动下载”。应针对具体网站检查，无需为完成模型下载而全局关闭安全检查。[Chrome 下载帮助](https://support.google.com/chrome/answer/95759?hl=zh-Hans)
