# 第一幕：夜色中的戈壁旅人

本次以 2026-10-29 的新要求为准，参考原 Word 方案中的相遇、避日、岩下交谈与朝歌旅程。第一幕现在在抵达朝歌入口时结束；夜行中的一颗、两颗飞星可观察记录，不再要求按键记录才能离场。

## 体验入口

Unity 打开 `Assets/_Project/Scenes/Traveller/01_GobiJourney.unity`，Play 后点击“开始旅程”。独立开发包是 `Builds/ActOneTraveller.app`。

macOS 可双击 `Tools/PlayActOne.command`，同时启动本机语音服务和试玩包；也可在项目根目录运行 `python3 Tools/play_act_one.py`。该入口默认使用离线剧情，不启用付费模型请求。

WASD 行走，Shift 快走，按住鼠标右键环顾，F 靠近人物交谈，T 切换玩家火把。交谈时可输入文字发送，或按住 V 录音，松开后等待中文转写；核对或修改文字，再点击发送。游戏不在后台持续录音。首次使用麦克风时由 macOS 显示授权提示，拒绝或无设备时仍能打字。

## 第一幕时序

| 阶段 | 触发与表现 |
| --- | --- |
| 夜间相遇 | 玩家与旅人举火把，夜空无太阳；先听到旅人的招呼，沿火光前行。 |
| 巨日升起 | 相遇约 12 秒后开始约 2 秒的天象变化。巨日真正出现后才启用日晒伤害，旅人加快奔向巨岩。 |
| 真实阴影避险 | 用朝向太阳的身体、头部射线判断遮挡，石壁、屋顶、山体等实体碰撞均能形成保护；不把“离掩体近”直接当作安全。 |
| 岩下交谈 | 玩家与旅人都到达掩体后，开始 **600 秒未暂停的游玩时间**。关闭聊天、点击“留在岩下等候”或一句 AI 回复都不能跳过等待。聊天继续计时，暂停与观察簿停止计时。 |
| 日晒灌木燃烧 | 双方进入掩体后，仅日晒的植物点燃，逐渐焦黑，约 32 秒后变成灰烬；阴影中的植物保留。粒子池最多同时显示 32 处近景火焰，远处植物仍按同样状态烧尽。 |
| 突然日落 | 600 秒结束后自动收束交谈，约 2 秒内转入夜晚，火把重新照明。 |
| 夜行到朝歌 | 沿原可通行路线前进，至少行走 35 米、经过 12 秒，抵达夜路终点且旅人在附近后自动转场。转场显示“数日之后／朝歌”，不再等 F 确认。 |

玩家生命值为隐藏的 100 点，首次进入日晒立即受伤 10 点，持续日晒每秒再受伤 10 点；进入阴影或日落后恢复满值。没有血条或数值显示。受伤使用红色屏幕边缘、轻微视角冲击；日晒中的 NPC 也有受热颜色反馈。晒伤至零时短暂淡出并回到巨岩检查点，保留本轮记录。

主要配置位于 `Assets/_Project/Settings/ActOne/GobiStory.asset`，包括等待、伤害、燃烧、夜行条件与首场景渲染预算。默认 90 FPS 上限、两倍 MSAA、70 米双级联阴影、LOD bias 1、Terrain 像素误差 15；退出第一幕后恢复之前的帧率、抗锯齿、阴影与地形设置。

新火把和灰烬采用可编辑建模生成，没有额外消耗混元额度。原始环境模型和下载归档保持不变；布景继续复用上一轮戈壁整合。

## 本机语音服务

### 2026-10-29 后续模型选型

针对当前 Apple M5 / 16 GB Mac 与 Unity 同机运行，已选 **MOSS-TTS-Nano-100M 的 ONNX CPU 版负责 NPC 发声，Qwen3-ASR-0.6B 的 MLX 8-bit 版负责玩家语音转文字**。这是待部署和实测的替换目标；当前游戏仍使用下文的 Vosk + macOS 临时语音，尚未下载或切换新模型。

MOSS 官方提供独立 ONNX CPU 推理、参考音频克隆和流式解码路径，适合作为减少 GPU 竞争的首选候选；同时需要配套的 `MOSS-Audio-Tokenizer-Nano-ONNX`。不把小模型直接视为音质胜出，也不默认它支持 CosyVoice 那样的自然语言情绪指令。[官方部署说明](https://github.com/OpenMOSS/MOSS-TTS-Nano#onnx-cpu-inference)

ASR 选择 `mlx-community/Qwen3-ASR-0.6B-8bit`，通过 `mlx-audio` 使用 Apple Silicon 推理；它是上游 Qwen3-ASR 的社区 MLX 转换版本。继续采用按住说话、松开识别、核对文字后发送，首先验证中文和游戏专名。模型文件大小不等于实际运行内存，也不套用官方大批量吞吐量作为本机交互延迟。[MLX 实现说明](https://github.com/Blaizzy/mlx-audio/blob/main/mlx_audio/stt/models/qwen3_asr/README.md)、[模型卡](https://huggingface.co/mlx-community/Qwen3-ASR-0.6B-8bit)

关键剧情台词提前合成并缓存，自由回复按短句合成；每个 NPC 固定声线。CosyVoice 3 留作音质比较候选。升级前用二十条实际台词试听，并在独立 Unity 游戏同时运行时记录延迟、识别错误、峰值内存、帧时间和打断行为。具体模型 ID、配套资源与验收项见 [选型记录](voice-model-selection.json)。

### 当前可用实现

当前电脑已安装依赖和识别模型。其他电脑可先执行：

```sh
python3 Tools/setup_voice_gateway.py
```

启动本机服务：

```sh
~/.cache/three-body-voice/venv/bin/python Tools/dialogue_gateway.py
```

服务监听 `127.0.0.1:8769`。Unity 上传 16 kHz 单声道 WAV 到本机识别，原始麦克风录音不保存，也不发给 DeepSeek。玩家确认发送后，才把文字作为一句对话处理。NPC 语音采用本机 macOS `say`，字幕始终保留；不依赖配音网络服务。

识别在独立常驻进程的主线程运行，复用已加载的轻量模型，避免边渲染边反复加载模型。单次识别有 28 秒处理上限，客户端等待上限 32 秒；取消聊天、暂停或关闭窗口会取消录音和待处理结果，系统授权窗口返回后也会重新检查是否仍处于交谈。自动化使用合成语音，不启动硬件录音。

可选完整模型：启动服务前设置 `TRAVELLER_ASR_MODEL` 为 `~/.cache/three-body-voice/models/vosk-model-cn-0.22` 的展开绝对路径。完整模型需要更多内存，当前 16 GB 机器默认使用轻量版。合成语音回环测试不代表实际麦克风、口音或嘈杂环境已经验收。

## AI 角色与 DeepSeek 接入

提示词位于 `Assets/_Project/Dialogue/Prompts/`。`shared.txt` 约束角色身份、可见事实、知识边界、短句回答和输出格式；各角色文件包含目的、语气、分阶段信息和行为限制。玩家提前提出正确解释时，角色应回应论据，不为拖延剧情捏造错误规律。

游戏发送角色 ID、当前阶段、已经见到的天象、观察记录、玩家假说和当前实例的有限历史。服务端组装提示词；角色不会共享其他实例的私下聊天。模型只能返回台词和五种表演意图（交谈、思考、警告、点头、看天），不能控制伤害、日落、燃烧、计时或场景切换。

没有启用在线服务时，界面明确显示“离线剧情”，采用预设回复，主线仍可完整运行。**目前未使用真实 DeepSeek 密钥验证在线生成**；接口适配测试使用模拟上游，不能当成真人自由对话或模型角色表现验收。

需要在线时，在服务端环境中设置 `DEEPSEEK_API_KEY`，可选设置 `DEEPSEEK_MODEL`，然后运行：

```sh
~/.cache/three-body-voice/venv/bin/python Tools/dialogue_gateway.py --online
```

密钥不写进 Unity 资源、场景或安装包。默认模型名按当前官方接口配置为 `deepseek-flash`，可通过环境变量替换；使用 Chat Completions、JSON 输出和关闭思考模式的短回复请求。接口依据 [DeepSeek 官方文档](https://api-docs.deepseek.com/api/create-chat-completion/)。超时或异常回退为明确的剧情回复，不把网络失败当成人物拒绝玩家。

## 制作与验证入口

1. `Blender --background --python Tools/prepare_act_one_props.py` 生成火把和灰烬的三档米制网格。
2. Unity 调用 `ThreeBodyProblem.Editor.ActOneProduction.Prepare()`，或菜单 `Tools → Three Body Traveller → Act One → Prepare Story Resources And Integrate`，导入材质、预制体、配置和角色装配。它保留当前三场景布局，不调用旧的全场景重建工具。
3. `ActOneProduction.BuildPlayer()` 构建专用 macOS 开发包。
4. 启动本机语音服务后，`python3 Tools/run_act_one_checks.py` 验证实际控制器、受伤、掩体、聊天、燃烧、夜行自动转场和六个视角性能。快速检查对 600 秒边界注入时间，报告会明确标记。
5. `python3 Tools/run_act_one_checks.py --soak` 真实等待全部 600 秒；`--journey` 验证后续完整主线。自动检查使用合成语音测试同一转写接口，不请求硬件麦克风权限或录下用户声音。
6. `python3 Tools/run_act_one_checks.py --characters` 验证三幕人物的实际手部 IK、火把、动作与坐姿表演。
7. `python3 Tools/test_dialogue_gateway.py` 验证八角色提示词、历史隔离边界、JSON 适配、超时回退和丢弃模型越权动作；`python3 Tools/check_voice_gateway.py` 用合成中文连续三次验证本机转写和临时配音。

验证结果以 `editmode.json`、`Native/*/report.json` 和最终交付审计为准。早期运行发现并修复了材质初始化时机、第一人称火把出画、场景光源开销与时序检查问题，相关原始记录保存在 `Diagnostics/`。
