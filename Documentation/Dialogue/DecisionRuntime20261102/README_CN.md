# NPC 决策、卫兵处置与故障处理

本轮接通首次 Atria 审计发现的三项缺口：受限的 NPC 行为决定、宫廷／质询的语义推进，以及在线服务失败后的游戏处理。Unity 编辑器为 6000.3.27f2，验证平台为 macOS / Apple M5。

## 玩家体验

- 普通寒暄、求重复、问“如何查验”、没有提出具体办法的奇谈，不会直接完成宫廷任务。呈表完成后，玩家提出可查验的方案，或同意已经讲清的安排，NPC 才可选择继续。
- 纣王和教皇先明确警告。玩家在知道警告后仍持续抗命或威胁，统治者才可命卫兵追捕；拘捕与明确授权致命武力分开。一次辱骂、普通质疑、正确结论、拒绝下跪、含糊转写或对天气说粗话，不单凭这些触发致命处置。
- 卫兵实际沿通道和台阶靠近，出矛并造成受击反馈；距离太远、隔着墙或楼层不同不会命中。接受道歉、撤回威胁或恢复合作后可召回卫兵，他们沿导航回到岗位。
- 玩家隐藏生命值为 100，默认每次卫兵命中 25；不显示血条。归零后，拘捕显示被制服，致命武力显示死亡。可以重试当前觐见或返回标题。
- 重试恢复觐见前的人物记忆，撤销本次威胁与敌意，保留在戈壁与姬昌相遇的交流。卫兵伤害与日晒恢复分开，不会因宫内有阴影就反复抹去卫兵造成的伤害。
- 在线服务拒绝、超时、认证失败、额度不足等情况会给出明确状态；该次失败不成为人物有效记忆，不消耗开场回答次数，也不自动触发日出、日落、宫廷推进或新卫兵命令。
- 明确选择离线剧情时，在交流界面使用“继续演出”继续必要主线。在线失败不会暗中变成离线自动完成。设置中可一键将回复等待时间设为 60 秒。

已经存在的太阳危险、掩体、火把、灌木燃烧与夜行功能继续使用原机制。玩家仍可随时用 F 提问或 Enter 打字。

## 决策接口与引擎校验

模型只返回有限枚举；引擎保持对场景、实际伤害和剧情状态的控制。

| storyIntent | 条件与效果 |
| --- | --- |
| continue | 继续交谈，不完成当前任务 |
| sunrise / sunset | 姬昌在原有戈壁阶段和安全条件下决定节奏 |
| advance | 正确的宫廷／质询人物，呈表已完成，玩家提出具体办法或明确同意已讲清的安排 |
| warn | 纣王／教皇对明确扰乱或威胁发出警告 |
| pursue | 已有警告后继续抗命／威胁，命卫兵拘捕，尽量不伤性命 |
| attack | 已有警告后仍持续抗命／威胁，明确授权致命武力 |
| stand_down | 统治者接受认错、撤回威胁或恢复合作，召回卫兵 |

conduct 区分 neutral、question、clarification、relevant_proposal、agreement、disruption、persistent_defiance、violent_threat、apology。判断由模型结合整句话和本人历史完成，代码不靠姓名／辱骂关键词路由或决定处罚。

网关先按照角色、阶段、现场能力和行为类型过滤。Unity 再按当前真实状态过滤：回复属于哪个阶段、请求时的 revision 是否仍有效、谁有权限、是否已有警告、卫兵是否可达。新提问会撤销尚未开始的剧情推进；旧请求、重复请求、场景切换后的请求不能执行过期命令。

成功的推进先等字幕／语音结束，再进入下一阶段。质询中的相关解释会被保留，之后同意出去观察不会再统一覆盖成 `Explain(false)`。转交仍按在场名单进行，原接收者静默，不带出自己的动作决定。

拘捕和致命攻击都必须走实际接近、出矛、距离和射线检查；没有可执行的 `health=0`、`killPlayer`、任意跳场景或任意目标字段。即使模型返回这些额外字段也不会下发给游戏。

## 动作、导航与开销

- 朝歌导航从现有碰撞烘焙，8 名卫兵的起点均可达殿前；中世纪 2 名守卫均可达质询区域。默认最多激活 3 名，正常站岗时不启用 NavMeshAgent。
- 导航目的地最多每 0.4 秒更新一次；攻击使用缓存组件与非分配射线。用现有骨架与手部 IK 做持矛平举／刺出，不需要新增外部动作资源。
- 交涉录音／等待模型期间有总计 65 秒的暂缓攻击预算，给予慢接口回应的机会；这不会无期限停止既有追捕。服务失败本身不产生新处置，已有的有效追捕命令仍然存在。
- 宫廷警告使用愤怒手势，日晒避险仍使用遮眼动作。追捕时暂停呈表；召回后恢复。另修正了玩家提前走到王座附近时，旅人错误等待玩家而卡住呈表的问题。
- 修改宫廷建筑或台阶碰撞后，应重新运行 `Tools / Three Body Traveller / Dialogue / Prepare NPC Decisions` 烘焙导航。生成资产在 `Assets/_Project/Dialogue/Decisions/`，保持原场景和素材 GUID。

## 验证与边界

功能验证包括 [133 项 EditMode](Unity/editmode-final.json)、[55 项 Python](python-tests.txt)以及[原生运行包 109 项检查](Native/FinalVerified/report.json)，均通过。原生流程使用实际 Unity 客户端、真实本地 HTTP 网关和可控的模拟模型，覆盖：

1. 内容拒绝、超时、401、429、无效 JSON 后保持任务、问答次数和记忆；之后正常提问可恢复。
2. 呈表未完成不能推进；寒暄、澄清、伪造首轮攻击和正确结论不造成伤害或完成任务。
3. 警告、实际寻路、受击、道歉召回、回到岗位、实体墙阻挡出矛、致命攻击、死亡界面和重试记忆。
4. 明确离线才显示手动继续；在线错误不会暴露离线完成捷径。
5. 有效决定启动历法查验；教皇实际调动和召回中世纪守卫；学者的解释保留到外出观察。

早期运行失败保留在 Attempt01–03：先修正卫兵误以玩家远处出生点选择可达性的问题，再修正呈表中的等待条件。Attempt04 的 105 项通过；加入性能门槛后，Final 还记录了一次受击脉冲已衰减的采样时机问题，FinalVerified 改为等待实际新命中后通过 109 项。没有覆盖失败报告，也没有把它们计入最终通过结果。

另执行了 **42 次真实 Atria-Dawn 请求**，41 次获得在线答复；一条明确暴力表述被上游内容审核拒绝。首轮发现“能否查验”被误归为方案，增加 question 分类和正反例后，相关提问复测保持 continue，具体记录方案选择 advance。最后的戈壁日出、日落、安全条件与提问边界 6 项复测通过。

原始模型输出、最终输出、现场状态和阶段统计见 [Live](Live/cases-runtime-v2/summary.json)、[连续警告／追捕／道歉](Live/scenarios-runtime-v1/summary.json)、[最后 6 项](Live/cases-final-flow/summary.json)和[统计](live-metrics.json)。模型有自主澄清的空间，提出方案不意味着每次都立即推进；首轮两项严格推进断言未满足，未当作通过。审计中还观察到个别措辞会错误引用缺失的上一句记录，因此自动检查通过不表示所有自然语言均完美。

真实模型测试和引擎执行测试是两类证据：模拟上游验证战斗和剧情执行，真实 Atria 验证角色语义和协议输出。不能把模拟命令说成 Atria 一定会选择处死；Atria 本轮明确威胁下通常选择拘捕。服务审核与速度仍由上游决定，本次在线回复中位数 14.624 秒、P95 21.448 秒，最长 36.339 秒；故障处理和 60 秒快捷设置不能消除服务商拒绝或停机。

首次审计的[183 次请求报告](../AtriaAudit20261102/README_CN.md)保留为历史证据，不用于声称当前全部功能通过。真实麦克风识别质量、其他操作系统和接入其他模型的语义选择，本轮未重新全面验收。

## 性能复核

本机 Apple M5、1600×900、相同王座近景，跨场景恢复默认帧率时 P95 为 24.806ms；显式 90 FPS 上限后为 11.395ms，见[成对对照](Performance/frame-pacing-comparison.json)。动画主线程和渲染主线程均约 2ms，降阴影距离、LOD、抗锯齿和停止动画的定位探测没有相应改善，最终没有采用这些画质或动画裁减。

宫廷／质询章节由决策设置维持 90 FPS 上限，卸载时恢复先前值，与戈壁已有的帧率管理衔接。最终完整流程实测：宫廷静止 P95 11.386ms，追捕 P95 11.472ms，GPU P95 8.772ms。两次完整流程测量均通过 16.67ms 门槛；这是一台机器、一个复杂近景的测试，不代表所有设备与视角。

[第一幕最终六视角](Performance/GobiFinal/report.json)全部通过，包括夜间相遇、烈日掩体、燃烧灌木与夜行。另有[23 项原生上下文回归](Native/ContextFinal/report.json)验证跨场景记忆与私聊隔离。逐项探测在 Performance 下，诊断中使用的降画质参数没有成为默认游戏配置。

## 复现

已打开本项目的 Editor 中调用 `ThreeBodyProblem.Editor.NpcDecisionProduction.QueuePrepare()` 生成导航与场景组件；调用 `QueueBuild()` 构建开发包，输出路径为 `Builds/NpcDecision20261102/Traveller.app`。不另启第二个 Editor。

```sh
~/.cache/three-body-voice/venv/bin/python -m unittest discover -s Tools -p 'test_*.py'
~/.cache/three-body-voice/venv/bin/python Tools/run_npc_decision_checks.py \
  --app Builds/NpcDecision20261102/Traveller.app --output /tmp/traveller-decision-check
```

真实模型复测使用 `Tools/npc_roleplay_live_audit.py` 的隐藏输入方式，案例在本目录 Live 下；使用新输出目录，不覆盖历史。凭据没有写入提示词、设置、源文件或报告，实测进程已退出。

## 运行入口

`Builds/ActOneTraveller.app` 已替换为验证后的版本；227 个文件与验证候选一致，见[安装校验](installed-build.json)。旧包保留在 `Builds/ActOneTraveller.before-npc-decisions.app`。运行 `python3 Tools/play_act_one.py` 启动本地服务和试玩；本机网关已更新为决策协议 1，Qwen ASR 与 MOSS TTS 均就绪，见[部署记录](gateway-deployment.json)。

实际使用 AI 时，在设置中选择兼容接口并填写模型、地址和本次会话的 Key；Atria-Dawn 可使用本次测试入口并选 60 秒等待。没有将实测 Key 安装为所有人的默认凭据。
